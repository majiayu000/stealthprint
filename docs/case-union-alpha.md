# Case study: union-alpha

[English](case-union-alpha.md) · [中文](case-union-alpha.zh-CN.md)

Fingerprint analysis of `stealth/union-alpha`, the anonymous free-preview model listed on OpenRouter on 2026-09-16 (price 0), performed end-to-end with this toolkit (`stealthprint`). OpenCode Zen (public and Go lines both list `union-alpha`) returned HTTP 500 for inference throughout the measurement window, so every datapoint below comes from the OpenRouter entry.

> **TL;DR:** `stealth/union-alpha` uses the **Llama-3 tokenizer (128K)** (15 discriminating probes × 12 repeats, zero deviation; reconfirmed by a mixed-backend-aware rerun) behind a **+16~17 token fixed template** (the constant drifts ±1 across sessions). It has a **real vision encoder whose billing formula is reverse-engineered**: `prompt_tokens = max(22, ceil(H/28)² + 6)` fits 11/11 size points with zero error — the Qwen2-VL-family tower shape, **cross-lineage** with the llama3 text vocab (a LLaVA-style assembly); red/blue ground truth passes (red 5/6, blue 3/4). Knowledge cutoff ≥ 2025-02 (continued training beyond official 3.1/3.3). **No native video**. Needle recall at 187K tokens is 3/3 exact. **Tool-calling fingerprint**: `tool_choice="none"` is completely ignored; parallel calls are the default. A **fusion-router-style front layer** sits in front of a single llama3-family backend, splitting requests across **counting/billing channels** (the secondary path's counts are producible by no known vocab and its behavior is identical to the majority path's — not a second model; channel weights drift over time and have **measurably flipped whole-epoch within hours** — during the B-channel takeover the generation-side ct modes 14/14/21 and echo fidelity stayed identical, so the model did not change), all reported by OpenRouter as `provider: "Stealth"`. Excluded: every GLM, Qwen3, DeepSeek, dots3, MiniMax, o200k, cl100k, Mistral-Nemo Tekken, Llama 4 (new 201K vocab), **Xiaomi MiMo-V2.5 (≡Qwen vocab, transitive exclusion)**, and **Meta's Muse family (muse-glimmer-30b measured = llama4 vocab 24/24, family-level inference)**. Of the community guesses, MiniMax M3.1 is directly excluded by tokenizer. **Epilogue (09-18): the preview ended and the deployer revealed the model as *Unbiased's Pareto* (self-described maker Circuit & Chisel); the paid successor `unbiased/pareto` is fingerprint-continuous — B-channel deltas 15/14/33/33 exact, ct mode 14, exact echo.**

### Mixed backends

The secondary (low) path's counts are **unstable across rounds** (fr probe 19→29, ru 34→30), match no local candidate vocab, and are not "majority + constant". Differential probes must pair within one path (majority mode; now codified in the library as `tokenizer --repeats`).

**Deep dive (2026-09-17 round 2: routing census + absolute-count pairing + echo behavioral split)**:

- **Majority path re-confirmed**: 4-probe deltas (zh 21 / fr 16 / digits 17 / emoji 28) all exactly llama3, identical to round 1.
- **Secondary-path counts do not close**: delta pairing gives a lone qwen3 hit (zh 15) vs a lone glm5 hit (fr 14) — mutually contradictory — and digits 33 / emoji 33/8 match zero of 11 candidates. Absolute pairing is harder still: **every one of the 11 candidates counts the base text at exactly 16; the secondary path reports 15 — no vocab can produce it**. The absolute values hop between "glm5 minus 1" (base/zh/fr: 15/30/29, then fails digits) and qwen3-line raw counts (digits 48) **across epochs** — the counter's own vocab drifts.
- **Ratio drift**: this round's base histogram is 15×8 / 33×5 — the secondary channel overtook the majority (round 1: 33×17 / 15×6). Routing weights follow time/load, not a fixed 70/30.
- **Behavioral split (decisive)**: echo probes ×N grouped by pt path — the low path scores 8/8 exact echoes, its completion_tokens modes (14, 21) equal the high path's, and the same hidden-reasoning long tails appear. A glm5/qwen3-line model cannot be generation-side identical to a llama3-line one (the ct modes are themselves a counting-vocab fingerprint).
- **Revised verdict**: round 1's "different backend/counter" attribution narrows to **counter** — a single llama3-family backend behind a fusion-router-style front layer that routes between **counting/billing channels**, not between models. The "dispatches to different models" hypothesis is rejected on behavior; "a front rewrite/re-count layer exists" is confirmed on counts (a half-confirmation of the fusion-router hypothesis).
- **Whole-epoch flip + axis tests (round 3b, answering the probe-homogeneity challenge)**: discriminating probes embedded in 8K/32K/128K contexts and inside code/math task framings — B-family counts appear at **every length and task framing** (8K/32K: zh 15, emoji 33, digits 33, fr 14; the raw 56/294/−17 pair deltas are all A/B base-straddle artifacts), so there is **no length- or task-triggered routing**; the same-epoch short-prompt control is also all B-family values (emoji 33 and 8 are precisely round-2's two recorded secondary-path values) — the ~30% B channel of hours earlier **flipped to dominant for a whole epoch** (the llama3-scale counter still appears, e.g. the 32K fr base). The generation side is unchanged throughout: echo 24/24 exact, ct modes 14/14/21 identical to round 2, the same hidden-reasoning tails, and all five identity framings (en/zh/maker/leading/projective) agree. **The instability axis is TIME, not request shape**; input counting and completion counting are severed — B rewrites prompt_tokens only, completion_tokens stays llama3-line in every epoch.
- **Difficulty axis + capability (round 4, user-requested "hard problems, e.g. Fermat's Last Theorem")**: six genuinely hard questions — Wiles' proof chain (EN/ZH), an adversarial planted-flaw fake proof (congruence-implies-equality), 2^1000 mod 125, smallest n with n! ending in exactly 2025 zeros, O(n log n) LIS with reconstruction — **6/6 correct** (4 machine-verified: mod-power = 1, n = 8115 with the exact Legendre sum, LIS passes 2000 random trials against an O(n²) oracle; the flaw question names the exact failing inference and validates the remaining steps; both outlines are historically accurate down to Taylor's role). Every hard question bills 70-120 invisible thinking tokens (ct 102-236 vs 30-100 visible) — the thinking path engages uniformly. Counting side: **all 6 hard questions land B-family** (every pt below the local llama3 raw count: 33<35, 19<29, 109<111), same-epoch echoes stay B-dominant (A survives as a 47=27+20 straggler); the probe-footer pair delta of 20 is exactly the A−B offset (another straddle artifact). **Difficulty does not trigger routing** — the last untested content axis agrees with length/task: the instability axis stays TIME. Capability (inference): well above small-model territory, consistent with a 70B-class post-training.
- **Easy/hard direct pairing (round 4b, user follow-up "did you ask easy vs hard separately?")**: 5 same-type pairs (mod-power / factorial zeros / FLT statement / summation / DP code), easy and hard versions asked as **separate interleaved calls in one epoch** — **9/9 correct** (easy: 24, 6, the theorem statement, 5050; hard: 1, 8115, the proof chain, 43 with the exact 7⁴≡1 mod 100 / 7⁷≡3 mod 4 argument; the LPS code passes 2000 random trials vs a brute-force oracle; only the easy code cell was eaten by rate limits). Counting: **within every completed pair easy and hard land on the SAME channel** (the fact pair hits A both times: 31=15+16, 46=30+16; the other pairs both-B/non-A, the fib pair exactly equals local counts both times) while neighboring pairs differ — assignment is difficulty-blind; the 4/4 within-pair agreement weakly suggests short-window affinity (n=4, recorded as an observation). Thinking path: **difficulty-correlated but not gated** — easy questions can carry hidden thinking (a 1-token answer "6" bills 39 invisible tokens), hard ones can carry zero (the LPS answer's ct=159=visible exactly); the switch is the model's own per-request decision (reasoning-model behavior), not a router.
- **Simple vs complex PROGRAMMING tasks (round 5, user-requested)**: 5 domain pairs (string/search/dp/graph/parse) — count-vowels vs regex-matching DP, binary search vs two-sorted-arrays median in O(log), stair-climbing vs edit distance, cycle detection vs Dijkstra, single-line CSV vs a full arithmetic evaluator — **every answer machine-graded against an independent oracle** (re.fullmatch, statistics.median, memoized recursion, Bellman-Ford, the csv module, eval; 1500-2000 random trials each): **10/10 correct on substantive inputs**, the only divergence being the empty CSV line ([''] vs the csv module's [] — both defensible conventions). Zero quality drop from simple to complex. Two initial FAILs turned out to be **our own oracle bugs** (the dijkstra oracle sorted directed edges into undirected ones; the csv generator emitted malformed unescaped lines) — the model code passed unchanged after repairing the oracles. Counting: all 10 calls B-family, 9/10 exactly local_llama3−2 (a stable B offset this epoch), 5/5 pairs internally same-channel. Invisible thinking: easy-code median 3 invisible tokens vs complex-code median 211 — with the two-array-median problem billing **599 invisible tokens (ct 841 vs 242 visible), the largest single hidden-thinking bill in the case**; contrasted with round-4b's LPS at exactly 0, thinking depth is per-task adaptive, not a difficulty gate.
- **Freeform generative test (round 6, evening; user-requested: "have the model build a Raiden-style game with free rein, Claude Code orchestrating")**: two clean HTTP-200-wrapped **504 "Provider timed out after 300158ms"** attempts established that a 24K-token one-shot generation cannot finish inside OpenRouter's fixed **300s provider timeout** on the free tier — the build succeeded **staged at ~3-4K completion tokens per call** (design 511 → partA 2989 → partB 3776 → partC 3637, with partB carrying 3.5K tokens of partA in context and reusing it consistently). Free rein honored — its own game **"Thunderwing: Deep Space Assault"**: graze-to-charge bomb, Web Audio synthesized sound, combo multiplier, a cat-squadron easter egg for no-damage boss kills, localStorage best score, touch support, and a prefers-reduced-motion accessibility adaptation. Behavior datapoint: asked for the closing segment without the code in context, the model **refused to write blind** ("my context only has the design list — writing the continuation cannot guarantee variable/interface/HTML consistency; paste the code first"), catching the orchestrator trimming context; with full code (pt 6353) it closed the file correctly. Verification: 394 lines / 26KB single HTML, `node --check` PASS, headless runtime smoke PASS — the initial "duplicate declaration" finding was our own harness concatenating the JS twice; **the model's code shipped with zero fix rounds**. Counting: the design prompt pt=107 = local 91 + 16 — **the A (llama3-scale) channel returned in the evening** after the afternoon's whole-epoch B dominance; the time-drift story continues.

The surviving explanation (matching the community analysis): an **undisclosed internal derivative** of Llama 3.1-70B/3.3-70B/405B with a vision adapter and a 262K window extension — post-training shops have this pipeline ready-made, but no public catalog SKU fits.

Offline `apply_chat_template` results characterize a published prompt format, but the hosted +16/17 value is an API usage count minus raw text, not the backend's serialized prompt. It also drifted between sessions. Without the gateway's exact serialization, matching a local constant cannot identify an individual Llama-3 derivative. The Pareto reveal resolved the identity question before a controlled trigger experiment could be run on the delisted preview endpoint.

### Epilogue: the deployer revealed itself (2026-09-18)

The preview ended and `stealth/union-alpha` now returns **404 with a self-reveal**: *"Thank you for participating in the Stealth Union Alpha testing period. This model was **Unbiased's Pareto**. Use it now: https://openrouter.ai/unbiased/pareto"*. The `stealth/*` namespace is fully delisted; the successor `unbiased/pareto` (same advertised 262,144 ctx; $2.5/$7.5 per M) answers the identity question as *"I'm Pareto, a model service made by **Circuit & Chisel**"* — no longer anonymous. A 7-call fingerprint of the successor shows **backend continuity**: echo fr 2/2 character-exact with the same **ct=14 mode** and a 117-token hidden-reasoning tail, and all four discriminating delta pairs land on **15/14/33/33 — exactly the B-channel signature** recorded as union's secondary path (round 2) and dominant epoch (round 3b), matching no known vocab (llama3 expects 21/16/17/28). The mystery counter that no tokenizer can produce turned out to be the product's own billing counter. (Maker name is the model's self-report; the "Unbiased" vs "Circuit & Chisel" naming relationship is unverified. The llama3-scale A counter did not appear in this sample — consistent with time-drift: which counting channel greets you depends on when you knock.)

Successor confirmed on every axis ever measured: llama3-line vocabulary directly, Qwen2-VL tower, missing tool_choice semantics, exact echo, ct mode 14. `unbiased/pareto` **is** the union-alpha backend, unmasked.

## Methodology notes (new in this case)

1. **OpenCode free-tier access**: OpenCode Zen free models reject bare API calls with `MissingSessionID` ("free tier can only be used in OpenCode"); any UUID in an `x-session-id` header unlocks it. `ChatClient` now sends one by default. **(Closed as of 2026-09-17 afternoon:** `/messages` now returns 403 `FreeTierError` "OpenCode's free tier can only be used from within OpenCode", identical with an `opencode/1.0.154` UA and with no session header — the gate moved server-side to provider Console; further OpenCode-side probing requires the real OpenCode client or a paid Go subscription.)
2. **OpenRouter usage semantics are not comparable across models**: named `meta-llama/llama-3.3-70b-instruct` (via DeepInfra) returned prompt_tokens inconsistent with vocab theory, with negative deltas — same-gateway named A/B (L7) is unusable on OpenRouter; tokenizer verdicts should rest on **local tokenizer comparison** (zero API cost, zero semantic ambiguity).
3. **"context-compression plugin" is OpenRouter gateway copy**, not an upstream fingerprint; the 262,144 it quotes is OpenRouter-side config. Real limits need needle measurement.
4. **HTTP 200 wrapping errors**: OpenRouter returns HTTP 200 + `{"error":{"code":502,...}}` for upstream 5xx — error-envelope analysis must parse bodies, not status codes.
5. **Age attestation is a model-level routing gate**: all `meta/muse-spark-*` variants (contributor included) return 403 with `missing_attestation_types: ["age_18plus"]` until the OpenRouter account completes 18+ confirmation — treat attestation status as a prerequisite when designing peer-comparison experiments; the same model can be measured on another gateway (OpenCode's free tier has no such gate).
6. **The wrapper constant drifts**: same probes, same vocab, two sessions: +17 → +16. Template constants are good for family-level judgments, not cross-session exact identity claims.
7. **OpenCode's Muse line speaks the Responses API**: `/zen/v1/chat/completions` returns 500 for Muse models; the working endpoint is `/zen/v1/responses` (`usage.input_tokens`). The gateway also filters by User-Agent — `Python-urllib/*` gets 403, a `curl/*` UA passes — and the free tier allows ~1 concurrent request (4 parallel = 403).
8. **Inside the llama3 vocab circle, discriminate by template constant, not vocab**: hermes-3 (llama3 vocab 24/24) has wrapper +10 vs union's +16/17 — a usable discriminator within the same-vocab family. But official-llama models on OpenRouter have usage polluted by prompt caching (deltas shifted +23~24, non-uniform), so the official-template anchor is unobtainable on that gateway.
9. **`min_pixels` floor is a measurable vision-tower signature**: DeepSeek V4.1-Flash (open weights) bills a flat **+184** for any image below ~544×544 — exactly the config's `min_pixels=295,936` upscale floor ((544/14)²/9 ≈ 168 + overhead), confirmed against its published `vision_config`. Both "flat for small images" shapes below are real encoders, but a *high* flat value (V4.1-Flash: 184, floor-enforced) vs a *floorless* flat value (union: 24, even 1×1) separates towers that a "flat vs slope" test alone would lump together.
10. **OpenCode's free tier is a paid catalog with a tiny free sample** (full census 2026-09-17): of the 71 listed models, 62 return 401 CreditsError, and only 4 are actually free-reachable (5.6%): `muse-spark-1.2/1.3-contributor-free` (both llama4 12/12 — the family exclusion now covers v1.2 too), `ling-3.0-flash-fin-free` and `nemotron-3.5-lightning-free` (both proprietary-vocab no-winner shapes). union-alpha stays 500 (upstream outage ongoing since 09-16); `deepseek-v4-flash-free` answers 400 "Model is unavailable" (pulled after the V4.1-Flash release). The error envelopes name the upstream provider "Console".
11. **Billing-curve formula fitting is a vision-tower family discriminator**: union's 11-point size curve fits `max(22, ceil(H/28)²+6)` exactly (Qwen2-VL family 28px/token + a 16-token floor + 6 overhead), while official Llama 3.2 Vision bills 1600 patches per tile into cross-attention and DeepSeek V4.1-Flash shows a min_pixels high-floor flat cost — three mutually distinct tower shapes. This upgrades the "flat vs slope" coarse test to **formula-family discrimination**, reverse-engineering both the tower family and its customized parameters (e.g., min_pixels).
12. **Endpoint identity drifts across epochs; single-epoch sampling misjudges**: union's counting-channel dominance flipped whole-epoch within hours (llama3 counter → B channel) while generation-side fingerprints (ct modes, echo fidelity) stayed constant — vocab "species" verdicts must be stamped with their sampling epoch. The "routes by length/task" concern was tested via 8K/32K/128K embedding and task framings, and the **difficulty axis** (Fermat's-Last-Theorem-grade problems) likewise triggers no routing: no content-axis routing on any axis tested; **the instability axis is time**.
