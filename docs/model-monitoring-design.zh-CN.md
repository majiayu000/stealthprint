# 模型监测上线设计与验收

状态：设计已实现。2026-10-20。用户已授权分析、实现、测试和上线；实际部署以文末实时记录为准。

## 目标与范围

让访客在一个公开页面上看到真实模型变化、原始依据、来源健康和完整日期。上线成功必须同时满足：采集能独立容错、历史可持久保存、网页公开可访问、定时工作流启用、线上数据与本次采集一致。失败标准：首次基线被报成新发布、网络故障制造下架事件、同 ID 修订丢失旧证据、静态链接失效、来源停止更新却仍显示正常。

复用当前网站和标准库 Python。新增生产能力限于现有采集模块、刷新脚本、页面状态展示及一个 Pages 工作流；历史数据放独立 `monitor-data` 分支。无数据库、消息队列、后台常驻服务、模型付费调用或新的凭据配置。

原工作区含未提交的网站与客户端改动。实施使用从最新 main 建立的 `feat/model-monitoring-live` 独立 worktree，只接入网站相关文件。原客户端改动留在原工作区。

## 数据与任务链路

1. GitHub Actions 每 5 分钟计划运行一次，也支持手动运行和 main 上的网站代码更新。逐个来源检查是否到期。
2. 读取 `monitor-data` 中的 `state.json`。七个来源为 AI Tracker Feed、AI Tracker 目录、OpenRouter 默认文本输出目录、models.dev 的 OpenCode 目录、HF DeepSeek 组织及两个官方 SDK 模型类型文件。
3. 来源独立请求和解析；HTTP 304 更新检查成功时间，失败保留该来源既有基线与证据并记录故障。遵守 Retry-After；不在一轮内反复重试。
4. 来源有效内容发生变化时保存 gzip 压缩的取证包，包含原请求 URL、响应状态、必要响应头和原文。包以 SHA-256 命名，状态和事件引用同一证据文件。认证头不进入包。
5. 每个目录首次成功只建立基线；之后记录新增、变化、当前未观察到及重新出现。滚动 Feed 离开窗口不等于撤回，不产生缺失事件。Feed 的公开消息保留来源发布时间；同 ID 修订保留前后版本。
6. 用每个来源自身的 ID 关联事件，不自动跨来源合并模型身份。SDK 用 AST 提取模型字面量及说明，不执行远端代码；纯排版不报变化。
7. 提交状态和证据到数据分支，再离线构建。只有构建和站点测试通过才部署 GitHub Pages。调度串行化，不同时写数据分支。
8. 静态站展示来源健康、上次成功、基线数量、新观测和已有 Tracker 历史；提供 JSON 及证据下载。目录基线不伪装成发布消息。线上停更时浏览器依据时间显示过期，不依赖再次成功构建才能报警。

现有 `site/updates.json` 保留为带原始日期的历史消息资料，不回填成新采集结果。设计比较页属于原工作区预览，不进入本次生产输出。

## 持久化约定

`state.json` 包含整体检查时间、按来源保存的基线/健康/下次检查时间及事件列表。来源状态保留当前已验证目录、缓存校验值及当前证据引用。每条事件包含来源、实体 ID、变化类型、本次观察时间、来源声明时间（有则保留）、前后值和前后证据引用。

原始取证包仅在关注内容变化时新增，既有包不重写。目录完整获取前不提交新基线；HF 沿同源分页直到结束。缺项只意味着本次目录未观察到，不宣布服务下架。首次状态为空时源失败仍可展示其他源及历史资料。

网页只复制状态与取证包，不复制数据分支的 `.git`。页面默认展示最近 200 组变化，完整历史可下载。展示事实不用数值置信度代替判断；官方发布、目录出现与入口实测保持明确区分。

## 测试与上线顺序

## 运行边界与回滚

GitHub schedule 可能延迟，不承诺分钟级 SLA。来源出现 530/429 时网站继续展示已有证据和故障；不把它描述为正常实时监测。整体调度停止时页面标记快照过期。

回滚先停用 `model-site` 工作流，保留数据分支；再回退代码并手动发布经过验证的版本。修复后恢复调度，继续从保存的状态运行。不得通过清空历史来恢复采集。

上线验收以真实状态和公开 URL 为准。7 天提前量、误报率与人工复核成本仍需后续观察，本轮不伪造长期效果。

## 独立来源扩展（Issue #31，2026-10-22）

目标：用公开上游材料独立发现新标识，让维护者能区分值得核对的候选与普通配置变化。是否继续扩源取决于新增证据、发现时间差、重复率与人工复核成本；只有噪声和维护负担时停止扩源。当前章节描述本次 PR 的实现，不代表已部署。

新增五个来源：Qwen、MiniMaxAI、moonshotai、mistralai 的官方 HF 组织，每 15 分钟完整分页；`@google/gemini-cli-core` 的 npm latest 构建，每小时检查。沿用已有来源隔离、证据归档及定时部署流程。当前覆盖范围见 `stealthprint/updates.py` 的固定来源列表。

### 公开构建文件差分

1. 读取 npm 元数据，只接受预期包名和 npm registry 下的对应 tarball，并校验 SHA-512 integrity。
2. 检查时不安装包、不执行 JavaScript、不解包写入磁盘。下载限 20 MiB，读取循环在 90 秒后终止；单次阻塞读仍受 25 秒 socket timeout 约束。检查归档头累计展开大小限 128 MiB，目标源码限 2 MiB；文件缺失、重复或为链接时失败。
3. 只读取 `package/dist/src/config/models.js` 中导出的简单 Gemini/Gemma 模型字面量，不扫描测试文件、注释、运行时赋值或自动路由别名。选定模型声明出现不支持的动态表达式时报告解析失败。它是明确且有限的公开代码观察范围，不能宣称覆盖客户端所有模型选择路径。
4. 按标识保存导出符号名和文件路径；版本号、排版变化不参与模型差分。同一完整包的 integrity 未变化时复用基线，避免再次下载。
5. 变化证据包含 npm 原始响应、包版本、下载 URL、完整包校验结果和选定源码的完整原文及 SHA-256；不保存整个 tarball。当前检查到的包版本与最近变化证据可不同，证据固定保留变化发生时的版本。
6. 首次采集只建立基线。之后记录新增、缺失、恢复和符号变化；损坏包、上游格式变化或下载失败均保留最后有效状态，不能制造整批模型消失。

### 人工核对入口

页面增加“含以下记录”筛选，可选择新标识、配置/状态变化或来源消息。新标识仅表示该来源新出现的 ID，SDK 则展示模型枚举新增项；恢复条目不重新算新候选。一个条目的后续价格或说明修改不抹去此前候选线索，筛选和搜索仍能找到它，查看消息经过可核对前后记录及证据。

本轮不提供自动身份判定。读者应核对源文件上下文、是否为已知别名、官方发布及实际入口，再决定是否做独立测量。HF 仓库新增也可能是量化、适配器或研究产物，不直接标成正式模型发布。分类器和主动通知仍为后续独立取舍，不依赖它们完成这次交付。
